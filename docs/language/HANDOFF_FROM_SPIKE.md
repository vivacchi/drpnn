## 0. なぜ DRPNN に来たか（ユーザーの定式化）

> 「対話のやり取りから**メロディラインのようなストリーミング**を学んで、
> **相手のストリーミングに共振**させるようにストリームできるモデルを作っている。
> 語彙とか単語、次の回答を探り当てるとかは、先に大規模で学習したモデルが出来上がらなければ
> 測定できない。人間の子供が言葉を覚える過程のように、視覚情報は欠けているけど、
> **文字の流れを音の流れと同じようにストリーミングで理解する**ようにする」

そして正しい順序は:

1. **ストリーミングのアーキテクチャを作る**（← DRPNN が既にこれ）
2. **大量の対話を食わせる**
3. **その後で、構造が生まれたかを測る**（測り方は**中身を指定しない**もの）

spike 側は 1 を飛ばして 3 をやろうとして 5 スライス失敗した。その失敗の記録が §2 以降。

## 1. 進め方（この 6 原理と衝突しない形）

DRPNN の禁止事項（CLAUDE.md）と、持ち込む着想の関係:

| 持ち込む着想 | 素の形 | **DRPNN での翻訳** | 衝突の有無 |
|---|---|---|---|
| **TTT**（学習＝推論時） | 内側ループで勾配ステップ | **既に実装済み**——「平衡としての学習」は TTT の極限。学習フェーズが存在しない | 衝突なし |
| **JEPA**（次の**表現**を予測） | 損失関数＋勾配＋崩壊防止正則化 | **STDP が局所時間で既にやっている**（pre→post で結合が育つ＝次に来るものの予測の物理形） | **素の形は禁止**（損失関数・勾配）。着想のみ |
| **MAMBA**（入力依存の状態選択） | 学習された選択ゲート・浮動小数 | **抑制ニューロン（76個）が担いうる役割** | **素の形は禁止**（浮動小数・勾配）。着想のみ |

**テキストはタイプ 1 入力として入る**: text → かな → 音素合成 → 蝸牛 → M1。
M1 から見れば**ただの音の流れ**であり、target も報酬も正解判定も無い。
したがって「M1 にタイプ 2 学習を入れない」に抵触しない。

## 2. 移せるもの — **たった一つの原則**（ユーザーによる要約・2026-08-25）

spike 側の 2 日間の失敗は、全部これ一つに帰着する:

> ## **何が正解か分からないものは、計量できない。**

当初この節には「計器についての 5 教訓」を書いていたが、ユーザーの指摘で**それらは
すべてこの一つの症状**と判明した:

| 当初「教訓」と書いたもの | 実際は |
|---|---|
| 帰無が情報を持たなかった（§33.6） | 正解を知らないから、**壊れた帰無と動く帰無を区別できなかった** |
| 帰無が構造を作った（§35.7） | 正解を知らないから、値が不自然に高いことに気づけなかった |
| 統計量が飽和していた（§35.9） | 正解を知らないから、AMI がいくつなら成功か言えなかった |
| 測っている当のものを壊していなかった（§35.10） | **「何を測っているか知らない」そのもの** |
| 人間の天井を先に取れ（§39） | ——これは教訓ではなく**処方**。正解の基準を作る作業だった |

5 番目だけが治療で、残り 4 つは症状。**根は一つ。**

### 2.1 この原則は「未知の構造を測る」計画にも刃を向ける

ユーザー自身の言葉:「そのパターンや規則性は**我々は現段階での正解を知らない。
モデルも知らない**」。原則を適用すると、**その未知の構造もまた計量できない**。
「何か構造が生まれたか」を測ろうとした瞬間、spike 側と同じ穴に落ちる。

### 2.2 逃げ道は DRPNN が既に持っている — **正解が実験の設計側にある量だけを測る**

M1 の既存評価を見ると、**正解が定義されている量しか測っていない**:

| 測っているもの | 正解の出どころ |
|---|---|
| 同一パターン再現性 0.953 | **同じ刺激を与えたのは実験者**。「同じ応答が返るべき」が既知 |
| パターン間分離 0.158 | **違う刺激を与えたのは実験者**。「違う応答が返るべき」が既知 |
| Kenet 2003 内部状態レパートリー t=4.169 | **生物で観測済みの既知現象**を再現できたか |

**「理解したか」は測っていない。「同じものに同じく、違うものに違って応じるか」だけを
測っている。正解は刺激を与えた側が持っている。**

テキストでも同じ形を取る（§6 の測定はすべてこの形に書き直すこと）:

- **同じ文を二度流したら、同じ状態軌跡が出るか**（正解＝実験者が同じ文を流した事実）
- **違う文なら違う軌跡か**（同上）
- **同じ話者の連続発話は、他人の発話より近い軌跡か**（正解＝話者 ID という既知の事実）

どれも「意味を理解したか」を問わない。**正解が実験の設計側にあるから計量できる。**

**規律の要**: 宣言 → 実装 → 実測 → 判定。**閾値は結果を見てから動かさない**。
撤回は撤回として残す（spike 側 §36 に撤回 10 件の一覧がある）。

## 4. 移せないもの — 勾配版 JEPA のレシピ（**参考として記すのみ**）

spike 側は言語 JEPA で 67 倍の改善を実測した（加法的・交互作用ほぼゼロ）:
規則ビュー +0.30 / 条件付け（中心化＋ZCA）+0.16 / SIGReg アニーリング +0.08 /
リスタート＋ランカー選択 +0.01〜0.08。

**このうち DRPNN に持ち込めるのは「規則ビュー」の着想だけ**——
**何を攪乱と宣言するか**（＝どの違いを違いとして扱わないか）。
文字ストリームでは、表記ゆれ・改行・語調をどこまで同一視するかが、
かな変換と音素合成の設計そのものになる。残り 3 つは勾配前提なので持ち込めない。

**Phase 0 の失敗機構（警告として持ち込む）**: 勾配版 JEPA は R²=0.0071 で崩壊した。
機構は「**構造化された低次元の攪乱が観測分散の大半を占めると、予測＋等方性は
情報のある部分空間を選ばない**」。DRPNN は勾配を使わないので同じ罠には落ちないが、
**「自己無撞着な悪い不動点」という失敗の形は共通しうる**——
自分の出力が自分の入力を作る系は、意味のない安定に落ち着ける。

## 6. これから（順序）

1. **日本語音節の網羅** — 現在 5 音節（pa, ki, tu, se, mo）→ 約 100 音節へ
2. **テキスト流し込み** — text → かな → 音素合成 → 蝸牛 → M1（タイプ 1 入力として）
3. **大量投入** — 上のコーパスを流す
4. **測定** — **正解が実験の設計側にある量だけ**を測る（§2.2）:
   - **再現性**: 同じ文を二度流して同じ軌跡が出るか（正解＝同じ文を流した事実）
   - **分離**: 違う文なら違う軌跡か（正解＝違う文を流した事実）
   - **共振**: 同じ会話の相手の軌跡は、**別の会話の相手**より近いか
     （正解＝話者と会話の対応という既知の事実）
   - **蓄積**: 文脈を伸ばすほど次への驚きが減るか
     （正解＝文脈長という実験者が操作した変数）
   **「意味を理解したか」は測らない。** それは正解を持たないので計量できない（§2.1）。

## 7. S1 実測 — 子音を実際に鳴らす（2026-08-25）

### 発見された欠陥

`src_phase2_f/phoneme_synth.rs` の `synth_consonant` は
`Plosive { burst_freq_low: _, burst_freq_high: _ }` と**帯域指定を両方捨てていた**。
摩擦音も `Fricative { .. }` で全部無視。`standard_syllables()` は
pa 500-2000 / ki 2000-4000 / tu 1500-3500 / se 3000-8000 Hz と別々の帯域を
指定しているのに、**合成器がそれを一度も読んでいない**。
結果、pa/ki/tu は構造的に同一波形（LFSR 状態差のみ）であり、
5 音素を分けていたのは母音 5 種と鼻音だけ。
**かな 100 種を流しても 6 通りにしか写像されない。**

### 宣言したゲート（実測前に固定）

蝸牛の子音窓（先頭 30ms）40 帯域スパイク数ベクトルについて:

- **G1**: 旧版で pa/ki/tu の相互コサイン類似度 = 1.000（欠陥の再現）
- **G2**: 帯域版で pa/ki/tu の相互類似度がすべて < 1.000
- **G3**: 帯域版の重心が帯域順 **pa < tu < ki < se**

正解の出どころ = **帯域を指定したのは実験者**（§2.2 の形）。
「音素として正しいか」は測っていない（正解を持たないので計量できない）。

### 実測（`cargo run --release --bin consonant_probe`）

| 音節 | 旧: 総スパイク / 重心 / 帯域数 | 帯域版: 総スパイク / 重心 / 帯域数 |
|---|---|---|
| pa | 23 / 2850Hz / 12 | 35 / 1935Hz / 19 |
| ki | 23 / 2850Hz / 12 | 22 / 2933Hz / 10 |
| tu | 23 / 2850Hz / 12 | 22 / 2778Hz / 11 |
| se | 113 / 2586Hz / 19 | **2 / 4000Hz / 1** |
| mo | 18 / 248Hz / 3 | 18 / 248Hz / 3（変更なし） |

**G1 PASS**（旧 pa/ki/tu 類似度 1.000000）/ **G2 PASS**（最大 0.947）/
**G3 PASS**（pa 1935 < tu 2778 < ki 2933 < se 4000）。

### 途中の失敗（記録として残す）

初版は**ピーク**を 9000 に正規化した。結果は**蝸牛が完全に無音**
（pa/tu/se とも総スパイク 0・G3 FAIL）。原因は基準の取り違えで、
蝸牛を駆動するのは包絡線 ≒ RMS でありピークではない。
実測 crest は母音 2.28 に対し帯域ノイズ 4.07-4.53 で、
**ピークを揃えると RMS が 1.8 倍不足する**。
目標値は `cochlea::FIRE_THRESHOLD` 200 の設計前提「純音 amp 8000 想定」から
RMS = 8000/√2 ≈ 5657 と導いた（ゲートを通すために選んだ値ではない）。
**訂正は 1 回のみ。通るまで回してはいない。**

### PASS が隠している事実 — `F_MAX_HZ` の天井

**se は G3 を通ったが、通り方が悪い。** 重心 4000Hz は蝸牛の最上帯域そのもので、
スパイクは **2 発・1 帯域だけ**（旧版は 113 発・19 帯域）。
`cochlea::F_MAX_HZ = 4000` に対し se の帯域中心は
√(3000×8000) ≈ 4899Hz——**帯域外**。/s/ のエネルギーは実際 4-8kHz にあるので、
現在の蝸牛は日本語のサ行をほぼ聞き取れない。G3 の PASS は
「上限に張り付いたので順序だけは合った」に過ぎない。

**これは設計判断なのでユーザーに委ねる**（`F_MAX_HZ` を上げると M1 の
既存実測値 — 選択性 0.795 / 再現性 0.953 / 分離 0.158 — の比較基盤が動く）。

- **案 A**: `F_MAX_HZ` を 8000 に上げる（サ行が聞こえる・M1 の既存数値は再測が必要）
- **案 B**: 4000 のまま（サ行は帯域制限で潰れる・既存数値との比較は保てる）

### 残る観察（調整はしない）

ki-tu の類似度 0.947 は高いが、これは指定帯域が
2000-4000 と 1500-3500 で大きく重なるため。**指定どおりの結果**であり、
バグではない。かな表を作る段でサ行/タ行/カ行の帯域を決めるときに再訪する。

## 8. 案 A（F_MAX を上げる）の検証 — **不成立**。ただし本命が出た（2026-08-25）

ユーザー判断で案 A を採択し検証した。**結論は「F_MAX_HZ は変えない」。**
しかし掘った先に、蝸牛そのものの欠陥が 2 件出た。そちらが本題になった。

### 8.1 いちばん重い発見 — **蝸牛の整数 biquad が自己発振している**

現行 production 設定 (F_MAX=4000・N_BANDS=40) で、
**40 帯域中 24 本のインパルス応答が 4000 サンプル走らせても減衰しきらない。**

```
帯域 0 fc=  50.0Hz  前半max|y|=1876  末尾max|y|=2491  ← 減衰どころか増大
帯域 1 fc=  70.1Hz  前半max|y|=1349  末尾max|y|=1349  ← 完全に無減衰
帯域 2 fc=  91.7Hz  前半max|y|= 770  末尾max|y|= 770
帯域 3 fc= 114.9Hz  前半max|y|= 490  末尾max|y|= 490
... 母音 F1 が乗る帯域も含む (/a/ 820Hz=帯域19、/u/ 331Hz=帯域10)
```

理論と合わない: 帯域 0 の極半径は r=0.994108 で、理論減衰は 1275 サンプル。
実測の n≥3900 末尾が 2491 ということは、**フィルタが自分の線形ダイナミクスに従っていない**。

**原因**: `BandpassBiquad::process` の `(acc >> 15)` は算術右シフト = floor なので、
負値側に直流バイアスが乗る。極が単位円のすぐ内側 (低周波ほど近い) だと、
このバイアスがリミットサイクルを維持・成長させる — 固定小数点 IIR の古典的病理。

**丸めモード比較** (F_MAX=4000・40帯域・4000サンプル・`biquad_limit_cycle` bin):

| 丸めモード | 残存帯域数/40 | 最悪の末尾 max\|y\| |
|---|---|---|
| `acc >> 15` (現行・floor) | **24** | 2491 |
| `(acc + (1<<14)) >> 15` (最近接) | **40**（悪化） | 1231 |
| **ゼロ方向切り捨て** | **0** | **0** |

ゼロ方向切り捨ては常に \|y\| を減らすので受動的な損失として働き、
リミットサイクルを**構造的に不可能**にする (固定小数点 IIR の定石)。

**DRP 移植性**: 除算器を使わずに書ける。
`acc / 32768` ≡ `(acc + (acc < 0 ? 32767 : 0)) >> 15` (シフト + 条件加算)。
全境界値で厳密同値をテストで固定済み (`magnitude_truncation_equals_division_without_divider`)。

**正解の出どころ**: 「安定な線形フィルタのインパルス応答はゼロに収束する」= フィルタ理論。
実験者側でもモデル側でもなく**数学側**にある。調整パラメータではない。

**出荷**: `BandpassBiquad::magnitude_truncation` (**既定 false = 従来とバイト同一**)。
`m0_cn_m1_pipeline` の CLI 第6引数で有効化。回帰テスト 4 件。

**独立確認**: 敵対レビューが独立に到達し、さらに定量化した —
「最低帯域の出力の **83% は算術右シフトの丸めバイアスであって音ではない**」。

### 8.2 二番目の発見 — **母音は F1 しか蝸牛に写っていない**

`FIRE_THRESHOLD = 200` は cochlea.rs に「純音 amp 8000 想定」と書かれている。
母音波形のピークは 7794 で確かに設計点にある。**しかし閾値は帯域ごとに効く。**
1 本の帯域に届くのは最強フォルマント F1 の振幅 4000 = 設計点の半分。

実測 (F_MAX=4000・圧縮後包絡線のピーク / 閾値 200):

| 母音 | F1 | F2 | F3 |
|---|---|---|---|
| a | **204** ○ | 167 × | 108 × |
| i | **216** ○ | 138 × | 131 × |
| u | **202** ○ | 177 × | 92 × |
| e | **203** ○ | 157 × | 112 × |
| o | **207** ○ | **190** × | 111 × |

全母音の符号が 138–216 に密集し、閾値 200 がその真ん中を切っている。余裕は **1〜8%**。
結果、**どの母音も帯域 1 本しか鳴らず、F2 は一度も鳴らない**。
/e/ と /o/ は F1 が同じ 500Hz なので**同じ 1 本を共有**する。

これは S1 の「ピークで校正したがノイズは RMS で効く」と同じ型の取り違え——
**校正した量と、効いている量が違う**。ここでは「波形ごとに校正し、帯域ごとに効く」。

副作用として、F_MAX を動かすと ERB 格子がずれ、母音が丸ごと on/off する。
無音になる母音の集合は F_MAX=4000→6000→7000→7500→8000 で
`{} → {a} → {a,e,o} → {a,i,u} → {}` と**非単調に振動**する。
「どの母音が生き残るか」は音響的性質でなく**格子と偶然の一致**で決まっている。

### 8.9 これで見えた壁の形

元の目的は「かな 100 種を流せるようにする」だった。そこに向かって、

1. 子音合成器が帯域を捨てていた → 直した (S1)
2. /s/ が蝸牛の外にあった → F_MAX を上げようとした (案 A)
3. **上げても良くならなかった。母音が格子の当たり外れで on/off するだけだった**
4. なぜかを掘ると、蝸牛が自己発振し、母音は F1 しか写っていなかった
5. **そして M0 を「良く」すると M1 の分離が悪化した**

壁の形はこうである: **M1 は、縮退した M0 に合わせて調律されている。**
M0 の符号を豊かにすると M1 はデフォルトアトラクタ側へ動く。
つまり「かなを増やす」前に決めるべきなのは、**M0 と M1 の動作点を一緒に置き直すか**であり、
それは音素 5 種を 100 種にする作業より大きい。ここが次の分岐点。
