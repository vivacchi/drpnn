## 0. なぜ DRPNN に来たか（ユーザーの定式化）

> 「対話のやり取りから**メロディラインのようなストリーミング**を学んで、
> **相手のストリーミングに共振**させるようにストリームできるモデルを作っている。
> 語彙とか単語、次の回答を探り当てるとかは、先に大規模で学習したモデルが出来上がらなければ
> 測定できない。人間の子供が言葉を覚える過程のように、視覚情報は欠けているけど、
> **文字の流れを音の流れと同じようにストリーミングで理解する**ようにする」

そして正しい順序は:

1. **ストリーミングのアーキテクチャを作る**（← DRPNN が既にこれ）
2. **大量の対話を食わせる**
3. **その後で、構造が生まれたかを測る**（測り方は**中身を指定しない**もの）

spike 側は 1 を飛ばして 3 をやろうとして 5 スライス失敗した。その失敗の記録が §2 以降。

## 1. 進め方（この 6 原理と衝突しない形）

DRPNN の禁止事項（CLAUDE.md）と、持ち込む着想の関係:

| 持ち込む着想 | 素の形 | **DRPNN での翻訳** | 衝突の有無 |
|---|---|---|---|
| **TTT**（学習＝推論時） | 内側ループで勾配ステップ | **既に実装済み**——「平衡としての学習」は TTT の極限。学習フェーズが存在しない | 衝突なし |
| **JEPA**（次の**表現**を予測） | 損失関数＋勾配＋崩壊防止正則化 | **STDP が局所時間で既にやっている**（pre→post で結合が育つ＝次に来るものの予測の物理形） | **素の形は禁止**（損失関数・勾配）。着想のみ |
| **MAMBA**（入力依存の状態選択） | 学習された選択ゲート・浮動小数 | **抑制ニューロン（76個）が担いうる役割** | **素の形は禁止**（浮動小数・勾配）。着想のみ |

**テキストはタイプ 1 入力として入る**: text → かな → 音素合成 → 蝸牛 → M1。
M1 から見れば**ただの音の流れ**であり、target も報酬も正解判定も無い。
したがって「M1 にタイプ 2 学習を入れない」に抵触しない。

## 2. 移せるもの — **たった一つの原則**（ユーザーによる要約・2026-08-25）

spike 側の 2 日間の失敗は、全部これ一つに帰着する:

> ## **何が正解か分からないものは、計量できない。**

当初この節には「計器についての 5 教訓」を書いていたが、ユーザーの指摘で**それらは
すべてこの一つの症状**と判明した:

| 当初「教訓」と書いたもの | 実際は |
|---|---|
| 帰無が情報を持たなかった（§33.6） | 正解を知らないから、**壊れた帰無と動く帰無を区別できなかった** |
| 帰無が構造を作った（§35.7） | 正解を知らないから、値が不自然に高いことに気づけなかった |
| 統計量が飽和していた（§35.9） | 正解を知らないから、AMI がいくつなら成功か言えなかった |
| 測っている当のものを壊していなかった（§35.10） | **「何を測っているか知らない」そのもの** |
| 人間の天井を先に取れ（§39） | ——これは教訓ではなく**処方**。正解の基準を作る作業だった |

5 番目だけが治療で、残り 4 つは症状。**根は一つ。**

### 2.1 この原則は「未知の構造を測る」計画にも刃を向ける

ユーザー自身の言葉:「そのパターンや規則性は**我々は現段階での正解を知らない。
モデルも知らない**」。原則を適用すると、**その未知の構造もまた計量できない**。
「何か構造が生まれたか」を測ろうとした瞬間、spike 側と同じ穴に落ちる。

### 2.2 逃げ道は DRPNN が既に持っている — **正解が実験の設計側にある量だけを測る**

M1 の既存評価を見ると、**正解が定義されている量しか測っていない**:

| 測っているもの | 正解の出どころ |
|---|---|
| 同一パターン再現性 0.953 | **同じ刺激を与えたのは実験者**。「同じ応答が返るべき」が既知 |
| パターン間分離 0.158 | **違う刺激を与えたのは実験者**。「違う応答が返るべき」が既知 |
| Kenet 2003 内部状態レパートリー t=4.169 | **生物で観測済みの既知現象**を再現できたか |

**「理解したか」は測っていない。「同じものに同じく、違うものに違って応じるか」だけを
測っている。正解は刺激を与えた側が持っている。**

テキストでも同じ形を取る（§6 の測定はすべてこの形に書き直すこと）:

- **同じ文を二度流したら、同じ状態軌跡が出るか**（正解＝実験者が同じ文を流した事実）
- **違う文なら違う軌跡か**（同上）
- **同じ話者の連続発話は、他人の発話より近い軌跡か**（正解＝話者 ID という既知の事実）

どれも「意味を理解したか」を問わない。**正解が実験の設計側にあるから計量できる。**

**規律の要**: 宣言 → 実装 → 実測 → 判定。**閾値は結果を見てから動かさない**。
撤回は撤回として残す（spike 側 §36 に撤回 10 件の一覧がある）。

## 4. 移せないもの — 勾配版 JEPA のレシピ（**参考として記すのみ**）

spike 側は言語 JEPA で 67 倍の改善を実測した（加法的・交互作用ほぼゼロ）:
規則ビュー +0.30 / 条件付け（中心化＋ZCA）+0.16 / SIGReg アニーリング +0.08 /
リスタート＋ランカー選択 +0.01〜0.08。

**このうち DRPNN に持ち込めるのは「規則ビュー」の着想だけ**——
**何を攪乱と宣言するか**（＝どの違いを違いとして扱わないか）。
文字ストリームでは、表記ゆれ・改行・語調をどこまで同一視するかが、
かな変換と音素合成の設計そのものになる。残り 3 つは勾配前提なので持ち込めない。

**Phase 0 の失敗機構（警告として持ち込む）**: 勾配版 JEPA は R²=0.0071 で崩壊した。
機構は「**構造化された低次元の攪乱が観測分散の大半を占めると、予測＋等方性は
情報のある部分空間を選ばない**」。DRPNN は勾配を使わないので同じ罠には落ちないが、
**「自己無撞着な悪い不動点」という失敗の形は共通しうる**——
自分の出力が自分の入力を作る系は、意味のない安定に落ち着ける。

## 6. これから（順序）

1. **日本語音節の網羅** — 現在 5 音節（pa, ki, tu, se, mo）→ 約 100 音節へ
2. **テキスト流し込み** — text → かな → 音素合成 → 蝸牛 → M1（タイプ 1 入力として）
3. **大量投入** — 上のコーパスを流す
4. **測定** — **正解が実験の設計側にある量だけ**を測る（§2.2）:
   - **再現性**: 同じ文を二度流して同じ軌跡が出るか（正解＝同じ文を流した事実）
   - **分離**: 違う文なら違う軌跡か（正解＝違う文を流した事実）
   - **共振**: 同じ会話の相手の軌跡は、**別の会話の相手**より近いか
     （正解＝話者と会話の対応という既知の事実）
   - **蓄積**: 文脈を伸ばすほど次への驚きが減るか
     （正解＝文脈長という実験者が操作した変数）
   **「意味を理解したか」は測らない。** それは正解を持たないので計量できない（§2.1）。

## 7. S1 実測 — 子音を実際に鳴らす（2026-08-25）

### 発見された欠陥

`src_phase2_f/phoneme_synth.rs` の `synth_consonant` は
`Plosive { burst_freq_low: _, burst_freq_high: _ }` と**帯域指定を両方捨てていた**。
摩擦音も `Fricative { .. }` で全部無視。`standard_syllables()` は
pa 500-2000 / ki 2000-4000 / tu 1500-3500 / se 3000-8000 Hz と別々の帯域を
指定しているのに、**合成器がそれを一度も読んでいない**。
結果、pa/ki/tu は構造的に同一波形（LFSR 状態差のみ）であり、
5 音素を分けていたのは母音 5 種と鼻音だけ。
**かな 100 種を流しても 6 通りにしか写像されない。**

### 宣言したゲート（実測前に固定）

蝸牛の子音窓（先頭 30ms）40 帯域スパイク数ベクトルについて:

- **G1**: 旧版で pa/ki/tu の相互コサイン類似度 = 1.000（欠陥の再現）
- **G2**: 帯域版で pa/ki/tu の相互類似度がすべて < 1.000
- **G3**: 帯域版の重心が帯域順 **pa < tu < ki < se**

正解の出どころ = **帯域を指定したのは実験者**（§2.2 の形）。
「音素として正しいか」は測っていない（正解を持たないので計量できない）。

### 実測（`cargo run --release --bin consonant_probe`）

| 音節 | 旧: 総スパイク / 重心 / 帯域数 | 帯域版: 総スパイク / 重心 / 帯域数 |
|---|---|---|
| pa | 23 / 2850Hz / 12 | 35 / 1935Hz / 19 |
| ki | 23 / 2850Hz / 12 | 22 / 2933Hz / 10 |
| tu | 23 / 2850Hz / 12 | 22 / 2778Hz / 11 |
| se | 113 / 2586Hz / 19 | **2 / 4000Hz / 1** |
| mo | 18 / 248Hz / 3 | 18 / 248Hz / 3（変更なし） |

**G1 PASS**（旧 pa/ki/tu 類似度 1.000000）/ **G2 PASS**（最大 0.947）/
**G3 PASS**（pa 1935 < tu 2778 < ki 2933 < se 4000）。

### 途中の失敗（記録として残す）

初版は**ピーク**を 9000 に正規化した。結果は**蝸牛が完全に無音**
（pa/tu/se とも総スパイク 0・G3 FAIL）。原因は基準の取り違えで、
蝸牛を駆動するのは包絡線 ≒ RMS でありピークではない。
実測 crest は母音 2.28 に対し帯域ノイズ 4.07-4.53 で、
**ピークを揃えると RMS が 1.8 倍不足する**。
目標値は `cochlea::FIRE_THRESHOLD` 200 の設計前提「純音 amp 8000 想定」から
RMS = 8000/√2 ≈ 5657 と導いた（ゲートを通すために選んだ値ではない）。
**訂正は 1 回のみ。通るまで回してはいない。**

### PASS が隠している事実 — `F_MAX_HZ` の天井

**se は G3 を通ったが、通り方が悪い。** 重心 4000Hz は蝸牛の最上帯域そのもので、
スパイクは **2 発・1 帯域だけ**（旧版は 113 発・19 帯域）。
`cochlea::F_MAX_HZ = 4000` に対し se の帯域中心は
√(3000×8000) ≈ 4899Hz——**帯域外**。/s/ のエネルギーは実際 4-8kHz にあるので、
現在の蝸牛は日本語のサ行をほぼ聞き取れない。G3 の PASS は
「上限に張り付いたので順序だけは合った」に過ぎない。

**これは設計判断なのでユーザーに委ねる**（`F_MAX_HZ` を上げると M1 の
既存実測値 — 選択性 0.795 / 再現性 0.953 / 分離 0.158 — の比較基盤が動く）。

- **案 A**: `F_MAX_HZ` を 8000 に上げる（サ行が聞こえる・M1 の既存数値は再測が必要）
- **案 B**: 4000 のまま（サ行は帯域制限で潰れる・既存数値との比較は保てる）

### 残る観察（調整はしない）

ki-tu の類似度 0.947 は高いが、これは指定帯域が
2000-4000 と 1500-3500 で大きく重なるため。**指定どおりの結果**であり、
バグではない。かな表を作る段でサ行/タ行/カ行の帯域を決めるときに再訪する。

## 8. 案 A（F_MAX を上げる）の検証 — **不成立**。ただし本命が出た（2026-08-25）

ユーザー判断で案 A を採択し検証した。**結論は「F_MAX_HZ は変えない」。**
しかし掘った先に、蝸牛そのものの欠陥が 2 件出た。そちらが本題になった。

### 8.1 いちばん重い発見 — **蝸牛の整数 biquad が自己発振している**

現行 production 設定 (F_MAX=4000・N_BANDS=40) で、
**40 帯域中 24 本のインパルス応答が 4000 サンプル走らせても減衰しきらない。**

```
帯域 0 fc=  50.0Hz  前半max|y|=1876  末尾max|y|=2491  ← 減衰どころか増大
帯域 1 fc=  70.1Hz  前半max|y|=1349  末尾max|y|=1349  ← 完全に無減衰
帯域 2 fc=  91.7Hz  前半max|y|= 770  末尾max|y|= 770
帯域 3 fc= 114.9Hz  前半max|y|= 490  末尾max|y|= 490
... 母音 F1 が乗る帯域も含む (/a/ 820Hz=帯域19、/u/ 331Hz=帯域10)
```

理論と合わない: 帯域 0 の極半径は r=0.994108 で、理論減衰は 1275 サンプル。
実測の n≥3900 末尾が 2491 ということは、**フィルタが自分の線形ダイナミクスに従っていない**。

**原因**: `BandpassBiquad::process` の `(acc >> 15)` は算術右シフト = floor なので、
負値側に直流バイアスが乗る。極が単位円のすぐ内側 (低周波ほど近い) だと、
このバイアスがリミットサイクルを維持・成長させる — 固定小数点 IIR の古典的病理。

**丸めモード比較** (F_MAX=4000・40帯域・4000サンプル・`biquad_limit_cycle` bin):

| 丸めモード | 残存帯域数/40 | 最悪の末尾 max\|y\| |
|---|---|---|
| `acc >> 15` (現行・floor) | **24** | 2491 |
| `(acc + (1<<14)) >> 15` (最近接) | **40**（悪化） | 1231 |
| **ゼロ方向切り捨て** | **0** | **0** |

ゼロ方向切り捨ては常に \|y\| を減らすので受動的な損失として働き、
リミットサイクルを**構造的に不可能**にする (固定小数点 IIR の定石)。

**DRP 移植性**: 除算器を使わずに書ける。
`acc / 32768` ≡ `(acc + (acc < 0 ? 32767 : 0)) >> 15` (シフト + 条件加算)。
全境界値で厳密同値をテストで固定済み (`magnitude_truncation_equals_division_without_divider`)。

**正解の出どころ**: 「安定な線形フィルタのインパルス応答はゼロに収束する」= フィルタ理論。
実験者側でもモデル側でもなく**数学側**にある。調整パラメータではない。

**出荷**: `BandpassBiquad::magnitude_truncation` (**既定 false = 従来とバイト同一**)。
`m0_cn_m1_pipeline` の CLI 第6引数で有効化。回帰テスト 4 件。

**独立確認**: 敵対レビューが独立に到達し、さらに定量化した —
「最低帯域の出力の **83% は算術右シフトの丸めバイアスであって音ではない**」。

### 8.2 二番目の発見 — **母音は F1 しか蝸牛に写っていない**

`FIRE_THRESHOLD = 200` は cochlea.rs に「純音 amp 8000 想定」と書かれている。
母音波形のピークは 7794 で確かに設計点にある。**しかし閾値は帯域ごとに効く。**
1 本の帯域に届くのは最強フォルマント F1 の振幅 4000 = 設計点の半分。

実測 (F_MAX=4000・圧縮後包絡線のピーク / 閾値 200):

| 母音 | F1 | F2 | F3 |
|---|---|---|---|
| a | **204** ○ | 167 × | 108 × |
| i | **216** ○ | 138 × | 131 × |
| u | **202** ○ | 177 × | 92 × |
| e | **203** ○ | 157 × | 112 × |
| o | **207** ○ | **190** × | 111 × |

全母音の符号が 138–216 に密集し、閾値 200 がその真ん中を切っている。余裕は **1〜8%**。
結果、**どの母音も帯域 1 本しか鳴らず、F2 は一度も鳴らない**。
/e/ と /o/ は F1 が同じ 500Hz なので**同じ 1 本を共有**する。

これは S1 の「ピークで校正したがノイズは RMS で効く」と同じ型の取り違え——
**校正した量と、効いている量が違う**。ここでは「波形ごとに校正し、帯域ごとに効く」。

副作用として、F_MAX を動かすと ERB 格子がずれ、母音が丸ごと on/off する。

### 8.9 これで見えた壁の形

元の目的は「かな 100 種を流せるようにする」だった。そこに向かって、

1. 子音合成器が帯域を捨てていた → 直した (S1)
2. /s/ が蝸牛の外にあった → F_MAX を上げようとした (案 A)
3. **上げても良くならなかった。母音が格子の当たり外れで on/off するだけだった**
4. なぜかを掘ると、蝸牛が自己発振し、母音は F1 しか写っていなかった
5. **そして M0 を「良く」すると M1 の分離が悪化した**

壁の形はこうである: **M1 は、縮退した M0 に合わせて調律されている。**

つまり「かなを増やす」前に決めるべきなのは、**M0 と M1 の動作点を一緒に置き直すか**であり、

## 10. 背景活動ノイズ（2026-08-25・ユーザー要望）

### 10.1 まず場所を間違えた — S9「耳」の自発発火は作れない

`M0_COCHLEA_DESIGN.md` §3.6 は 2026-05-24 に

記載し `// cochlea.rs (Step 3 で実装)` と書いていたが、**実装されていなかった**。
実装して掃引した結果:

| 振幅 | レート中央値 | 個体差クラス別 |
|---|---|---|
| 12 | 83.6 Hz | [0, 0, 170, 399] |
| 16 | 221.3 Hz | [0, 41, 399, 400] |
| 32 | 400.0 Hz | [43, 400, 400, 400] |

**レートが 0 / 170 / 400 Hz に張り付き、中間が無い**（G13 FAIL）。
`FireGenerator` は**閾値＋不応期**の装置なので、閾値未満は 0 Hz、
超えたら不応期で決まる 400 Hz（= 2000 step/s ÷ 5）しか出せない。
**滑らかな自発発火率を作れない構造。** 設計書の「50-100 Hz」も
0 と 400 が混ざった見せかけの中央値だった。

→ ご希望の「脳内の活動ノイズ」は耳（蝸牛の閾値発火器）では作れない。

### 10.2 「今あるのはメトロノームであってノイズではない」

- `cochlear_nucleus.rs` は 3 細胞型すべて `spontaneous_input = 0`
- **`thermo_neuron.rs` のコメントは「現在: spontaneous_input=0 (受信専用)」と書いているが、
  コードは `spontaneous_input: 2, leak: 1`** — ドキュメントとコードが乖離している
- そして本質: **`spontaneous_input` は定数駆動**なので各ニューロンは規則的に発火する。
  `idx % 4` はニューロン**間**の個体差にすぎず、**時間方向の不規則さを与えない**

JEPA でノイズが果たす役割（崩壊の防止・対称性の破壊）には時間方向の不規則さが要る。
そこで `ThermoNeuron::spontaneous_jitter`（膜電位への LFSR 揺らぎ・既定 0）を実装。
膜電位なので閾値装置と違いグラデーションが作れる。原理 3 のため乱数でなく LFSR。

→ **M1 は単発の摂動に完全に頑健**。壊しているのはカオス的増幅ではなく**累積**。

### 10.9 訂正 — 混同の指標が 2 つあって逆を向いていた（2026-08-25）

§10.7 で「再現性を落とさずに異音素間の混同だけが減った」と書いたのは**不正確**。
ユーザーの「背景ノイズなしで測定した結果と並べて教えて」で 4 指標を並べたところ、
**異音素間の混同を測る指標が 2 つあり、互いに逆を向いている**ことが判明した。

| 指標 | ノイズなし | 疎ノイズ4/16 | 差 | 改善したシード |
|---|---|---|---|---|
| selectivity | 0.7178 | **0.7178** | **±0.0000** | 3/5 |
| within（再現性） | 0.9466 | 0.9602 | +0.0136 | 4/5 |
| **between（試行ごとの混同）** | 0.2288 | 0.2426 | **+0.0138（悪化）** | **2/5** |
| **per-pair（平均指紋の混同）** | 0.5282 | 0.4910 | **−0.0372（改善）** | **5/5** |

`selectivity = within − between` なので、
**within の +0.0136 と between の +0.0138 がほぼ完全に相殺**して差が ±0.0000 になっている。
「変化なし」は無変化ではなく**打ち消し**である。

**読み方の違い**: per-pair は 20 試行を**先に平均してから**比べるので試行ノイズが落ち、
系統的な成分だけが残る。between は個々の試行のまま比べるので試行ノイズを含む。
つまり疎ノイズは「**平均すれば**表現をより区別可能にするが、
**1 試行だけ見れば**むしろ少し紛らわしくする」。

**判定への影響**: 宣言した G24/G25 は per-pair 基準で書いたので**そのまま PASS**。
しかし**指標を変えると結論が変わる**以上、「疎ノイズは効く」とは言えない。正確には:

> 疎ノイズは、平均表現の区別可能性（per-pair）を 5/5 で上げるが、
> 試行単位の分離（between）は 3/5 で下げ、両者を合成した選択性は変わらない。

**ユーザー判断（案イ・2026-08-25）: 既定 OFF のまま据え置く。**
テストで固定済み（`cochlea_spontaneous_defaults_off` /
`spontaneous_jitter_defaults_off_network_wide` / `spontaneous_jitter_defaults_off`）。
既定実行が正準ベースライン 0.699（seed 42）を正確に再現することも確認済み。

**次に決めるべきこと（ユーザー判断待ち・未着手）**:
per-pair と between の**どちらが目的に近いか**。これは
「1 試行で当てたいのか、平均表現が区別できればよいのか」という問いであり、
**ストリーミング理解という最終目的（§0）に照らして決まる**。
指標を先に決めないと、この先の測定はどちらにでも転ぶ。

**教訓**: 今回は「per-pair だけを見て案アを推奨」→「並べたら支持が消えた」という
順序をたどった。§2 の根本原則の系として、
**同じ概念に複数の計器があるときは、全部並べてから結論を書く**。

## 11. F0 実装の前に止まった — 独立監査で 3 件の critical（2026-08-25）

ユーザー承認のうえ「Vowel に F0 を足し、声帯パルス列＋フォルマント共鳴に変える」に
着手する直前、15 エージェントの独立監査（3 レンズ × 反証）を回した。
**9 件が反証を生き残り、うち 3 件が「F0 を今すぐ実装するな」と言っている。**

### 11.1 最優先 — **入力層のガードが死んでいる**（実測で確定）

`ThermoNetwork::new` のガード:

```rust
if n.spontaneous_input == 0 && n.leak == 0 {
    // 入力ニューロンは個体差なし (パターン入力のみで動く)
    continue;
}
n.spontaneous_input = (idx as i32) % 4;
```

`ThermoNeuron::input()` の現在値は **`spontaneous_input: 2, leak: 1`**。
ガード条件は**常に偽**なので continue されず、入力ニューロンにも `idx % 4` が配られる。

**実測（`jitter_probe` に検査を追加）**:

```
入力ニューロン数 84 / 無音で発火したもの 43 個
最大発火率 135.2 Hz
spontaneous_input の分布: {0:21, 1:21, 2:21, 3:21}
leak の分布: {1:84}
ガード条件に掛かる入力ニューロン: 0 個
```

レビュアの独立実測ではさらに「**完全無音 1 秒で M1 出力層が 616 spike**」。
1/4 が約 66Hz、1/4 が約 133Hz、半数が 0Hz。

**これは設計書 §3.6 の決定（一律 2）でも §3.6.1 の復旧案（一律 0）でもない第三の構成**で、
意図されていない。`thermo_neuron.rs:196` のコメント「現在: spontaneous_input=0（受信専用）」は
同じ関数の :217 と矛盾する死んだドキュメント。

**含意**: 本セッションの母音・M1 測定は**すべてこの上で取られている**。
M0.5 設計書 §1.1 の「M1 は音素入力にほぼ反応せず入力非依存のデフォルトアトラクタに落ちる」の
交絡要因として最有力。**蝸牛側（F0/倍音）の議論より先に切り分ける。**

### 11.2 「母音は F1 しか写らない」の閉じた式

包絡線の平衡は `env = 2^ENV_LEAK_SHIFT × mean|x| = 16 × (2/π)A = 10.19A`。
圧縮後 `sqrt(10.19A)` が `FIRE_THRESHOLD = 200` を超える条件は:

> **A ≥ 3927**（帯域に届く正弦振幅の床）

母音の振幅は **F1 = 4000（床の 1.9% 上）/ F2 = 2000–3200 / F3 = 800–1600**。
**偶然ではなく算術で決まっていた。** F2/F3 は構造的に床の下。

**これが F0 計画を直撃する**: 倍音にエネルギーを分けると 1 本あたりの振幅が下がるので、
素直にやると鳴らなくなる。レビュアの実測:
「RMS 一致にすると **/a/ 群は F0=100/150/200 すべて沈黙**する一方、他母音は一部だけ鳴る」。

## 12. M0 を先に正しくする（2026-08-25・ユーザー指示）

> 「フォルマントの区別がこの問題のポイントのような気がするんだ。だから、先にフォルマントの
> 認識ができるようにしよう。そして M0 がちゃんと機能してから M1 に取り掛かろうよ」

### 12.1 M0 のゲート（正解が完全に実験者側にある形）

- **G29 被覆**: 各母音の指定 3 フォルマントの最寄り帯域が応答するか（5×3 = **15/15**）
- **G30 場所符号**: 5 母音の発火帯域**集合**が全 10 対で相異なるか（10/10）
- **G31**: 無音母音なし
- **G32 精度**: 発火帯域のうち指定フォルマント近傍（±1）の割合
- **G34′ 穴**: 純音を **3 レベル**（最弱フォルマント/その2倍/最強）で 200 点掃引し、
  **最悪値**で応答しない周波数の数
- **G35**: 全帯域でインパルス応答がゼロに落ちきるか

**G32 と G34′ が要**: G32 が無いとゲインで全帯域を鳴らして G29 を満点にできる。
G34′ が無いと帯域を狭くして「聞こえないから精度が上がる」を通してしまう。
**両方あれば、沈黙でもゲイン殴りでも通らない。**

### 12.2 現行の M0 は「最大精度・最小被覆」の端にいた

| | 被覆 | 場所符号 | 精度 | 母音ごとの発火帯域数 |
|---|---|---|---|---|
| 現行 | **5/15** | 9/10（e/o 衝突） | 100% | [1,1,1,1,1] |

閉じた式: `env = 16×(2/π)A = 10.19A` → `sqrt(10.19A) ≥ threshold` ⟺ **`A ≥ threshold²/10.19`**。
閾値 200 で床は 3927、母音は F1=4000 / F2=2000-3200 / F3=800-1600。
**F1 は床の 1.9% 上、F2/F3 は構造的に床の下**。偶然ではなく算術だった。

### 12.3 発見: 足りないのは選択性（設計書 §1.5 の OHC・未実装 4 件目）

閾値を下げて F3 を拾おうとすると、F1 のスカートが多数の帯域を鳴らす。
**ゲインと閾値は同じ比を動かすだけ**（対角線上の設定がすべて同じ値になる）。
効くのは **Q（フィルタの鋭さ）** という独立の軸だった。

設計書 §1.5:「外有毛細胞（OHC）は周波数選択性を **1/3 oct → 1/10 oct** まで鋭くする。
**これがないと『補聴器をつけても言葉が聞き取れない』**（sensorineural hearing loss の典型症状）」
——**未実装**。症状の記述がそのまま今の状態だった。

### 12.5 いちばん大きい発見: 穴の正体は幾何ではなく**量子化**だった

帯域数を増やしても穴が頭打ちになった:

```
穴の数/200   Q×1  Q×2  Q×3  Q×4
帯域 40       15   68  118  147
帯域 240      13   37   50   60   ← 頭打ち
```

残差 13 個は**すべて 50-65 Hz**、そして**最強レベルなら全部聞こえる**（= レベル依存）。

原因: 低周波では `b0 = alpha/a0` が極端に小さく（50Hz・ERB Q で約 192/32768 = 0.0059）、
1 サンプルあたりの寄与が数十しかない。そこに**ゼロ方向切り捨ての損失**が乗ると、
低振幅入力では立ち上がる前に削られる。
しかも **`alpha` は 1/Q に比例**するので、
**選択性を上げようとするほど低域が聞こえなくなる**悪循環だった。

**修正**: `BandpassBiquad` の状態 `y1`/`y2` を **i64 の Q8 表現**にして、
再帰の途中で整数に丸めないようにした（係数は Q1.15 のまま、返り値も整数スケールのまま）。
**整数のまま桁を増やすだけ**なので原理 4（整数演算）に一切触れない。

**効果**:

```
穴の数/200        修正前                    修正後
帯域数  Q×1 Q×2 Q×3 Q×4      Q×1 Q×2 Q×3 Q×4
   40    15  68 118 147   →     1  27  67  97
   80    13  37  61  93   →     0   0  10  28
  120    13  37  50  65   →     0   0   0   4
  240    13  37  50  60   →     0   0   0   0
```

**低域の穴 13 個が完全に消え、頭打ちも消えた。**
量子化損失が「帯域数では解けない壁」を作っていたのであり、外したら**純粋な幾何の問題に戻った**。
幾何なら帯域数で買える。

回帰テスト `weak_low_frequency_tone_is_heard`（50/55/60/65Hz・振幅3200 が発火すること）を追加。

### 12.11 律速は圧縮器ではなく出力段（監査の決定的な実測）

監査が独立に示した:

> `compress_sqrt` は**出荷経路に情報を 1 ビットも足していない**。
> 圧縮器を外して生 `env` を 14400（= 120²）で直接判定した対照が、
> **母音 5 個すべてでスパイク列がビット単位一致**した。
> `isqrt(env) >= 120` は `env >= 14400` と厳密に等価であり、
> `FireGenerator` が**単一の絶対閾値**で二値化する限り、
> 任意の単調・無記憶な圧縮器 f と閾値 T の組は水準集合を 1 個決めるだけで、
> **自由度はスカラ 1 個に潰れる**。

さらに: 設計書 §3.4 の `log2_int` は env 閾値を **2 の冪にしか置けない**ので、
現行動作点 14400 を再現できない。**log への差し替えは動的レンジの獲得ではなく
閾値配置分解能の純損**。

**含意**: 未実装項目のうち「対数圧縮」は**律速ではない**。
直す順序は **出力段（FireGenerator）→ その後に圧縮器 / AGC**。
逆をやると作業が丸ごと無駄になる。

**出力段の実測**（1ch の rate-level 関数）:
上限 400 Hz ちょうど（= 2000 step/s ÷ (1+`FIRE_REFRACTORY_STEPS`)）で、
**閾値を跨いだ瞬間にそこへ飛ぶ**。閾値→飽和は fc により **0.50〜3.25 dB**。
0 でも max でもない中間レートが出る振幅は掃引の **0.6〜3.6%** しかない。
原因は「**発火が env にも膜電位にも戻らない**」構造そのもの
（積分器リセットなし・閾値適応なし）。

なお低域だけ窓が広く見えるのは**レベル符号ではなくリップル**。
`ENV_LEAK_SHIFT` を 4→7 に伸ばすと fc=307Hz の窓は 2.25→0.25 dB と高域に収束する。
**「動的レンジが改善した」と主張するときは、必ずこの対照を取ること**（監査の提案を採用）。

**禁止する直し方**（監査の指摘を採用）:
`FIRE_THRESHOLD` を下げる / `FIRE_REFRACTORY_STEPS` を増やす /
`ENV_LEAK_SHIFT` をいじって窓を広く見せる — いずれもパラメータ調整でゲートを通す類。

**リップル対照の結果と、自分の対照の不備**:

**両方の設定で一貫して +6 dB** なので改善は平滑の副産物ではない。
ただし **`ENV_LEAK_SHIFT` を変えると平滑だけでなく実効利得も 8 倍変わる**ので、
この対照はリップルだけを分離できていない（不備として記録）。

**監査との数値の食い違い（記録）**: 監査は旧モードの動的レンジを 0.50–3.25 dB としたが、
本測定は 20.50 dB。監査は定常状態、本測定は**170ms の刺激全体**（パイプラインが実際に見る窓）。
どちらも正しく、下流に効くのは後者。

**レベル不変性は直らない（予測どおり）**: `spike_cost=480` でも G40/G41/G42 は全 FAIL。
床を変えていないので当然。むしろ崩壊が −15 → −12 dB と早まる
（レート ∝ レベルなので低レベルでは総スパイクが減り、170ms 窓で「1 度でも発火」する帯域が減る）。
**レート符号と低レベルの場所符号はトレードオフの関係にある。**

**監査の指摘を 1 件反証**: 「M1 が見るチャネルにはレベルが一切残らない。
M0.5 bushy は −24〜0 dBFS の全域で 24 Hz 固定」→ **集団としては成立しない**。
実測で M0.5 は各レベルで M0 のスパイクを 95% 以上通す
（0dB: 802→764、−6: 326→322、−12: 114→108、−18: 58→57）。
個別チャネルのレートが飽和していても、集団の総数はリクルートメントでレベルに追随する。
**出力段の修正は M1 に届く。**

### 12.13 レベル不変性に残る道と、その難しさ（監査の指摘）

G40/G41/G42 を通すには **AGC** が要るが、監査が 2 つの壁を実測で示した:

- **教科書的 AGC は 6 原理に直撃する**: 「参照レベルで割る」= 原理 2 の
  『target_rate との比較』、「全帯域の和」= 原理 1 の『平均活動レベル』。
- **帯域ごとの分割型 AGC（per-channel divisive）は場所符号を構造的に破壊する** —
  実測で全レベルで 1/5 に崩壊。

**まだ検証していない監査の指摘（要対応）**:
- 「**フォルマント振幅比 (1.0 : 0.7 : 0.3) が完全に消える。母音表の ×4 はこの副作用の対症療法だった**」
  ← §12.8 で入れた ×4 への直接の批判。未検証。
- 「M0.5 の Octopus は coincidence detector ではなく leaky integrator になっており、
  子音より母音で多く発火する（オンセット検出が逆転）」
- 「M0.5 の entropy 適応は有界でない — 60 音節で実効閾値 43 倍、応答 30→2 発。
  『適応』ではなく**累積失聴**」← 長い刺激列を流すときに効く。コーパス投入の前に要対応。

### 12.14 累積失聴の確定 — 本セッションの M1 測定すべてに掛かる交絡

同じ音節を 120 回連続提示（`cumulative_deafness` bin）:

| 提示回 | M0 スパイク | M0.5 スパイク | M0.5 発火ch数 | Octopus |
|---|---|---|---|---|
| 1 | 869 | **859** | 74 | 86 |
| 2 | 869 | **511**（59%） | 74 | 47 |
| 10 | 869 | 251 | 74 | 20 |
| 120 | 869 | **129（15%）** | 74 | **4（4.7%）** |

- **G47a M0 の保存率 100.0% → PASS**（蝸牛に適応が無いので当然。対照として正しく機能）
- **G47b M0.5 の保存率 15.0% → FAIL**
- **G47c 回復**: 10 秒の無音を挟んでも **27%** までしか戻らない
- `reset()` を呼んでも呼ばなくても同じ（15.0% vs 15.7%）。
  **`ThermoNeuron::reset_state` は `local_entropy` を意図的に保持する**ので reset は無意味
- **発火ch数は 74 のまま**。場所は保たれ、**レートだけが失われる**

**交絡の範囲**: `n_train=100` なら訓練で 100 回、`evaluate` でさらに 20×5=100 回の提示がある。
**測定時点で M0.5 は既に 15〜20% まで落ちている。**
§8.3 で「n_train=500 で基準が 0.767→0.581 に下がるのは M1 側の別問題」と書いたが、
**これで説明がつく。** 本セッションの M1 数値はすべてこの上で取られている。

**原因は散逸の形**:

```
entropy_per_spike = 80、entropy_decay_rate = 1、entropy_decay_interval = 5
→ 0.2/step。80 を散逸するのに 400 step (200ms)。
それより速く発火すれば際限なく溜まる。**上限が無い。**
```

**根本は「散逸が一定レート（線形）」であること。**
物理的には**放熱は温度差に比例**する（ニュートンの冷却則）。
比例散逸 `local_entropy -= local_entropy >> shift` なら平衡点
（`生成レート << shift`）が存在して有界になる。
これは `EnvelopeDetector` が既に使っている形と同じで、
**DESIGN_PHILOSOPHY §11 の「エントロピー散逸 = 熱の自然減衰（放熱）」により忠実**。

監査も独立に同じ診断: 「**線形散逸には時定数が存在しない**・平衡発火率が刺激レベルに依存しない」。

**未着手（ユーザー判断待ち）**: 散逸を比例形にする変更は `ThermoNeuron` の
熱力学的中核に触れる（M1 の全ニューロンが entropy を持つ）ので、
CLAUDE.md「設計哲学の根本に関わる変更は必ず合意を取る」に従って提案のみ。

### 12.15 累積失聴の修正 — 比例散逸（ニュートンの冷却則）

ユーザーの定式化:
> 「平衡点とはいっても、**使われなければ冷めていく**という認識でいいよね。
> **最低限発火するものに関してはある途中の平衡点に至る**けどね」

これがそのまま実装の形を決めた:

```rust
// 散逸 = 比例項 (放熱 ∝ 温度差) と 一定レート の大きい方
let proportional = self.local_entropy >> self.entropy_decay_shift;
self.local_entropy -= proportional.max(self.entropy_decay_rate);
```

- **比例項**が高エントロピー側で**平衡点**を作る（ニュートンの冷却則。
  DESIGN_PHILOSOPHY §11 の「エントロピー散逸 = 熱の自然減衰（放熱）」に忠実。
  一定レートで放熱する物体は存在しない）
- **一定レート**が下限として「**使われなければ 0 まで冷める**」を保証する。
  これが無いと整数演算で `entropy < 2^shift` のとき比例項が 0 になり、
  **残留が永久に残る**（監査が `EnvelopeDetector` について指摘したのと同じ欠陥）
- `shift` は当てはめず既存定数から導出:
  **`2^shift ≈ entropy_per_spike / entropy_decay_rate`**。
  旧実装が「1 発火ぶんを散逸しきる時間」として設計していた時定数そのもの

**結果**:

| 提示回 | M0.5 スパイク（前 → 後） | Octopus（前 → 後） |
|---|---|---|
| 1 | 859 → **990** | 86 → **95** |
| 2 | 511 → **856** | 47 → **73** |
| 120 | **129（15%）→ 850（86%）** | **4 → 72** |

- **G48 有界性 PASS** — 5 回目以降**完全に平坦**
- **G49 適応が生きている PASS** — 刺激内で M0.5 は 0.85–0.88（M0 は 1.00–1.03 = 対照どおり）
- **G51 決定論性 PASS**
- **G50 M1 を壊さない → FAIL**

### 12.16 壁の形が最も鮮明になった — M1 は欠陥の「疎さ」に依存している

**予測が外れた記録**: 「累積失聴が直った分 M1 は改善するはず」と書いたが**逆だった**。

| 42 | 0.771 / pp 0.352 | **0.560 / pp 0.462** |

M1 の入力が疎になり、それが M1 の選択性を支えていた。
直したら入力が 5.7 倍になり、M1 は飽和側へ動いた。

これは「M0 がちゃんと機能してから M1 に取り掛かろう」という
ユーザーの方針の正しさを裏づけている。

**M1 の再調律は M0 が固まってから、別フェーズとして行う。**
現時点の M1 数値（selectivity 0.56）は「M0 が正しくなった状態での出発点」であって、
劣化ではない。

### 12.17 rate code の本当の理由 — ×4 が壊したものを回復する（G52）

監査の指摘:
> 「**フォルマント振幅比 (1.0 : 0.7 : 0.3) が完全に消える。母音表の ×4 は
> この副作用の対症療法だった**」

**自分で測って確認した**（`level_axis` の G52）。旧モード（`spike_cost=0`）:

| 音素 | 指定振幅 (F1,F2,F3) | 発火数 (F1,F2,F3) | 順位 |
|---|---|---|---|
| a | (16000, 11200, 4800) | **(66, 66, 65)** | × |
| u | (16000, 12800, 3200) | **(65, 66, 64)** | × |

**振幅が 3.3 : 1 の差なのに発火数はほぼ完全にフラット。G52 は 0/5 で FAIL。**
理由は全部が飽和していること。

**私の ×4 がこれを引き起こした**: 元は F1=4000（床の 1.9% 上）で F2/F3 が床の下。
×4 で F2/F3 を床の上に押し上げた代わりに、**F1 を飽和域に押し込んだ**。
「フォルマントが鳴るようにした」引き換えに「**フォルマントの強度差を消した**」。
監査の「対症療法だった」は正確。

**rate code がこれを回復する**:

| spike_cost | G52 |
|---|---|
| 0（旧） | **0/5 FAIL** |
| 120 | 2/5 FAIL |
| **240 / 480 / 960** | **5/5 PASS** |

spike_cost=480 の発火数 **(172, 78, 28)** は指定振幅 **(16000, 11200, 4800)** の比を
（sqrt 圧縮ぶん縮んだ形で）保っている。

> **`×4` と rate code は対。どちらか片方だけでは正しくない。**
> ×4 が F2/F3 を鳴らし、rate code がその代償の飽和を防ぐ。

**採用規則（実測前に宣言）**: G52（5/5）かつ G45（無音床）かつ G46（0dB 場所符号）を
満たすうち **G43 動的レンジが最大** → 240: 24.00 dB / **480: 26.50 dB** / 960: 26.00 dB
→ **`FIRE_SPIKE_COST = 480` を既定に採用**。

**これはレベル不変性（G40–G42）を直さない。** それは AGC の課題として別に残る。

**固定した契約（テスト）**:
`fire_generator_respects_threshold`（旧モードの契約・明示指定）/
`fire_generator_integrates_and_consumes`（既定の契約: 閾値未満は 1 発も出ない、
超過分が溜まって消費される、入力が大きいほど発火率が高い）/
`formant_intensity_rank_survives`（G52）。

## 13. F0（音程）の実装と、設計点への訂正（2026-08-25）

### 13.1 実装したもの

- **`FormantResonator`**（全極 2 次共鳴器・Klatt 型）。
  `cochlea::BandpassBiquad` は共鳴器として使えない（監査の指摘・実測）:
  RBJ bandpass は **0 dB peak gain 正規化で一切増幅しない**、2 極 2 零なので
  下側スカートが −6dB/oct、`erb_q_factor` は Q 上限 9.264。
  状態は蝸牛と同じく **i64 Q8**（低周波・高 Q で整数丸めに削られるため）。
- **`glottal_pulse_train`**: 三角波パルス列。**パルス幅で −12dB/oct の傾斜を作る**
  （後から傾斜を掛けるのではない・監査の指摘）。整数周期なので折り返さない。
- **`synth_vowel_f0`**: 声帯パルス列 → 3 つの全極共鳴器。
  倍音が F0 間隔で並び共鳴器が振幅を形づくる = 本物の音声と同じ構造。
  **`synth_vowel`（純音3本）は変更しない**（過去ログとの連続性）。
- **RMS を `synth_vowel` に揃える**: 声帯パルス列は F0 が高いほど倍音が減り
  1 本あたりが強くなるので、源の振幅を固定すると**音量が F0 に依存**する。
  それでは音程不変性でなく音量を測ってしまう。

### 13.2 ゲート（実測前に**完全に**指定）

前回 G26 を「F0 の値も指標も沈黙の扱いも別母音側の F0 も未宣言」と監査に批判されたので:

- F0 値: 100 / 150 / 200 / 250 Hz ・ 指標: 発火帯域集合のコサイン
- 沈黙: どれか 1 条件でも無音なら FAIL ・ 別母音側は同じ F0 集合すべてで比較
- **G53**: F0 を変えたら応答が変わる ・ **G54**: 同一母音・F0違いの**最小** > 別母音・同F0の**最大**

### 13.3 結果 — G53 PASS / G54 FAIL、そして失敗の形が重要

| Q | 同一母音F0違いの最小 | 別母音同F0の最大 | G54 |
|---|---|---|---|
| 1x | **0.2075** | 0.9999 | FAIL |
| 2x | 0.0727 | 0.9997 | FAIL |
| 3x | 0.0142 | 0.9993 | FAIL |
| **6x（出荷値）** | **0.0000** | 0.9992 | FAIL |

**仮説の半分は当たった**: Q を下げると同一母音の類似度が改善する（0.0000 → 0.2075）。
**Q の鋭さが倍音を分解して音程不変性を壊している**のは事実。

**しかし本当の問題は別側**: **別母音・同F0 がどの Q でも 0.999**。
同じ F0 なら**全母音が同じ周波数に倍音を持つ**ので、
**どの帯域が鳴るかは母音でほとんど変わらない**。
フォルマントは発火**率**を変えるだけで、**帯域の集合を変えない**。

> **倍音のある本物の刺激では、場所符号は「F0 の櫛」に支配され、母音には支配されない。**

純音 3 本のときと**正反対**（純音版は倍音が無いので場所符号 = フォルマントそのものだった）。

### 13.4 §12.7 の設計点への訂正

**`N_BANDS=80` / `Q×6` という設計点は「倍音の無い刺激」で最適化したもの。**
実音声（倍音あり）では最適点が違う。

**純音 3 本という刺激そのものが、測っていた対象を歪めていた。**
今セッションで繰り返した「**計器が答えを決める**」の、**刺激版**。

§12.7 の表（母音精度 92.5% など）は**純音刺激での数字**であり、
実音声に一般化しない。かな 100 種やコーパスに進む前に、
**倍音つき刺激で設計点を取り直す必要がある。**

### 13.5 次に切り分けるべきこと（未着手）

「別母音・同F0 が 0.999」の原因候補:
1. **帯域が飽和して「ほぼ全部鳴る」状態**になっており、count ベクトルの変動が
   フォルマントでなく倍音位置に支配されている
2. 高域帯域が**非分解**になってフォルマント包絡を追うべきなのに、
   Q×6 では全域が分解されている（Q×1 でも 0.9999 なので、これだけでは説明しきれない）
3. 指標（コサイン）が飽和している可能性 — 0.999 台で 4 桁表示なのは
   §12.10 で踏んだ「飽和を 4 桁表示が隠す」と同じ形かもしれない

**3 は自分の計器の疑いなので、先に潰すこと。**
